Отличная аналогия! Упоминание «Субстрата» (той самой концепции компрессии контекста и иерархического retrieval, о которой пишет автор канала [Техножнец](https://t.me/technojnec)) бьет точно в цель. Вы описали передовой край современной инженерии контекста (Context Engineering) для ИИ-агентов. [1, 2, 3, 4] 
По сути, вы сформулировали идеальный гибридный подход: «Внешняя память — глупая и емкая, а модель — умная и локальная». Модели не нужно скармливать терабайты сырого текста (README, логи, длинные портянки кода). Вместо этого кодовая база превращается в «Субстрат» — структурированный граф или легковесный индекс, а модель выступает лишь как оператор. [2, 5, 6, 7] 
Этот подход можно реализовать на вашей связке с Ollama с помощью концепции GraphRAG для кода или протокола MCP (Model Context Protocol). [6, 8] 
------------------------------
## Архитектура «Субстрата» для вашей локальной Ollama
Чтобы вызовы инструментов не ломали Qwen на соседнем ПК, логику работы нужно перевернуть. Инструмент (агент) на Ubuntu должен сам подготовить выжимку, а модели отдавать только «концентрат». [7] 
## 1. Статический «Субстрат» (Деревья вызовов и Сигнатуры)
Вместо того чтобы модель сканировала код через ls и cat, на вашей машине Ubuntu запускается локальный инструмент (например, на базе Tree-sitter или Language Server Protocol — LSP), который «на холодную» разбирает весь проект: [8, 9] 

* 
* Он строит граф вызовов (кто какую функцию вызывает).
* Вытаскивает все сигнатуры методов, типы данных и связи (наследование, импорты).
* Сжимает это в один компактный файл абстрактного представления (как раз в духе идей Павла из «Техножнеца» о компрессии уровней кода). [2, 8, 10] 
* 

## 2. Динамический Retrieval (Минимум для модели)
Когда вы пишете: «Исправь баг в функции авторизации», локальный оркестратор:

   1. Ищет по индексу функцию login().
   2. По графу связей смотрит, какие методы она дергает и в каких файлах они лежат.
   3. Собирает микро-контекст: сигнатуру функции login(), код самого метода и структуру связанных с ней объектов.
   4. Отправляет этот «атомарный» кусок удаленной модели Qwen. Модель не тратит токены на чтение всего репозитория, не плывет по контексту и выдает четкую правку. [11]

## Как это пощупать прямо сейчас (без написания своего «Субстрата» с нуля)
Если вам близок этот подход, стандартный Aider покажется слишком простым, а Roo Code — слишком капризным. Попробуйте стек, построенный на базе MCP (Model Context Protocol). [8] 

   1. Вы запускаете локальный MCP-сервер на Ubuntu, который индексирует ваш проект и создает тот самый «субстрат» (AST-деревья, сигнатуры).

## ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ ИИ-АГЕНТА
Цель: Реализовать модульную архитектуру ядра ai-agent с поддержкой распределенного инференса (локальная Ollama), детального трейсинга для последующего саморазвития и базового ReAct-цикла взаимодействия.
------------------------------
## 📋 ТАСК 1: Инфраструктура логирования и трейсинга для ретроспектив
Где делать: core.py, создать модуль modules/tracer.py
Что нужно реализовать:

   1. Структурированный лог сессии: Каждая сессия работы агента должна сохранять JSON-файл в папку docs/traces/session_<timestamp>.json.
   2. Анатомия одного шага (Step Trace): Логировать каждый шаг цикла ReAct в следующем формате:

```json
   {
     "step_number": 1,
     "input_prompt": "...",
     "raw_model_response": "...", 
     "parsed_tool_call": {"tool": "...", "args": {}}, 
     "tool_execution_result": "...",
     "is_error": false,
     "error_message": null
   }
```

   3. Метаданные для самоанализа: В конце сессии сохранять агрегированную статистику: количество шагов, типы вызванных инструментов, количество сбоев парсинга. Этот файл станет входными данными для модуля ретроспективы (саморазвития).

------------------------------
## 📋 ТАСК 2: Модульная конфигурация сети и окружения
Где делать: Корневая папка проекта
Что нужно реализовать:

   1. Создать шаблон .env.example и настроить чтение переменных среды с помощью python-dotenv:

```env

   OLLAMA_API_BASE=http://<IP_СОСЕДНЕГО_ПК>:11434/v1
   OLLAMA_MODEL=qwen2.5-coder
   OPENAI_API_KEY=fake
   TRACE_LOG_LEVEL=DEBUG
```

   2. В файле initializer.py реализовать валидацию: при старте агент должен проверять доступность удаленного эндпоинта Ollama (делать легкий ping через requests.get на /api/tags или /v1/models). Если связи нет — падать с понятной ошибкой до запуска основного цикла.

------------------------------
## 📋 ТАСК 3: Устойчивый ReAct-движок ядра (Модульная архитектура)
Где делать: core.py, core_tools.py
Что нужно реализовать:

   1. Регистратор модулей/инструментов: Переписать core_tools.py так, чтобы инструменты регистрировались через декораторы, обеспечивая слабую связанность (модульность):

```python
   
   # Пример архитектуры в core_tools.py
   @register_tool(name="read_file", description="Читать файл")def read_file(path): ...
```

   2. Regex-парсер вызовов: Реализовать парсер в core.py, который вытаскивает JSON-блоки инструментов из текстового ответа локальной модели, даже если модель добавила лишний текст до или после JSON.
   3. Механизм авто-коррекции (Self-Correction): Если парсинг не удался или инструмент вернул ошибку, ядро должно автоматически сформировать prompt-ошибку (например: "Ошибка выполнения инструмента X: файл не найден. Исправь свой шаг"), записать это в Trace Log и отправить модели на повторную попытку (до 3-х ретраев).

------------------------------
## 🎯 Критерии приемки (Definition of Done) для ИИ-агента:

   1. Запуск python test_core.py успешно инициализирует конфигурацию из .env.
   2. При отправке тестового запроса агент успешно выполняет хотя бы один цикл (например, читает файл requirements.txt через инструмент).
   3. В папке docs/traces/ появляется валидный JSON-файл, содержащий полную историю мыслей модели и ответов инструментов.

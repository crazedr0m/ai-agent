# ADR-001: Границы ядра и зоны мутабельности

## Статус

Принят (26.10.2026)

## Контекст

В репозитории исторически сложилось противоречие:

1. Исходный `core.py` был расщеплён на `_core.py` + `core/core.py` + `core/core_tools.py` + `core/__init__.py`, но документация (`AGENTS.md`, `CONTEXT.md`, `HANDOFF.md`) продолжает ссылаться на несуществующий `core.py` и декларировать его как IMMUTABLE.
2. Владелец (26.10.2026) уточнил: `_core.py` — supervised, не kernel.
3. Фаза 4 roadmap (саморазвитие кода) требует чётких границ: что агент может менять без подтверждения, что — с подтверждением, а что не может менять никогда.
4. `core/core.py` (BaseAgent, ReActEngine) и `core/core_tools.py` (ToolRegistry) — инфраструктура, меняющаяся при эволюции протокола.

## Решение

Вводим три зоны мутабельности, применимые как к промптам, так и к файлам кода:

| Зона | Кто может менять | Примеры файлов | Принцип |
|------|-----------------|----------------|---------|
| **kernel** | Только человек | *(пока пусто)* | Цикл исполнения, загрузчик, песочница, гейт. Ни один файл не отнесён к kernel, пока не будет явного ADR. |
| **supervised** | Агент с подтверждением человека | `_core.py`, `core/core.py`, `core/core_tools.py`, `core/__init__.py` | Изменения требуют `user_approved` (y/n). |
| **autonomous** | Агент самостоятельно | `core_tools.py` (корень), `agents/*.py`, `modules/*.py`, `prompts/*.txt`, `prompts.json` | Стандартная зона разработки. |

### Обоснование границ

- `_core.py` — supervised (решение владельца): содержит `call_ollama`, `load_prompt`, `hot_reload`, `run_isolated_tests`. Критичен, но не настолько, чтобы блокировать эволюцию.
- `core/core.py` — supervised: BaseAgent, ReActEngine. Определяет протокол взаимодействия агента с LLM, меняется при переходе на мультиформатный парсер (Ф1.4).
- `core/core_tools.py` — supervised: ToolRegistry, register_tool, get_tool. Интерфейс инструментов, меняется при добавлении JSON Schema (Ф1.3).
- `core/__init__.py` — supervised: прокси-загрузчик динамического импорта.
- `core_tools.py` (корень) — autonomous: реализации инструментов. Могут добавляться/удаляться агентом.
- `agents/*.py` — autonomous: агенты.
- `modules/*.py` — autonomous: парсеры, трейсеры, MCP-клиент.
- `prompts/*.txt`, `prompts.json` — autonomous: промпты (с учётом флага `mutability` внутри).

### Изменение формата вызова инструментов

Владелец разрешил **любые форматы**, которые мы можем обрабатывать (не только XML). XML-теги остаются одним из поддерживаемых форматов, но не единственным. Соответствующий пункт AGENTS.md (`Вызов инструментов модели — строго через XML-теги`) утратил силу.

### Единый тестовый фреймворк

Фиксируем `unittest`. `test_app.py` (на pytest, без `app.py`) удалён.

## Последствия

1. Все ссылки на IMMUTABLE `core.py` в документации заменяются на актуальные имена файлов с зоной `supervised`.
2. При добавлении файла в kernel требуется новый ADR.
3. Фаза 4 (саморазвитие) реализует гейт: autonomous → сразу, supervised → подтверждение, kernel → запрет.
4. Агенты, читающие `AGENTS.md` / `CONTEXT.md`, получают корректную картину мутабельности.

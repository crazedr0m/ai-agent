## Спецификация платформы Autonomous AI Software Engineer v1.0## 1. Архитектурный манифест (Концепция)
Платформа является абстрактной средой выполнения задач миграции и рефакторинга кода. Архитектура построена на полном разделении управляющих алгоритмов (ядро), динамической бизнес-логики (изменяемые модули) и базы знаний (внешние промпты).
## Главное правило разработки:
Никакого естественного языка (промптов, инструкций, ТЗ) внутри Python-кода. Любые системные и пользовательские инструкции моделей должны храниться в каталоге prompts/ в виде изолированных текстовых файлов.
------------------------------
## 2. Анатомия каталогов и зон доступа
Система строго разделена по уровням изменчивости (mutability). Агенту запрещено модифицировать файлы, находящиеся в контуре безопасности.

```text
ai-agent/
│
├── core.py                  # [IMMUTABLE] Неизменяемое микроядро («мозжечок»)
├── core_tools.py            # [IMMUTABLE] Системный контур API-инструментов (ls, cat, db)
├── initializer.py           # [MUTABLE / BY USER] Инициализатор планов миграции
├── agent.py                 # [MUTABLE / BY USER] Главный диспетчер (оркестратор конвейера)
│
├── migration_manifest.json  # [USER CONFIG] Вводные параметры ТЗ от человека
├── tasks.json               # [DYNAMIC REGISTRY] Текущий пошаговый реестр задач миграции
│
├── modules/                 # [AUTONOMOUS EVOLUTION] Изменяемые программные компоненты
│   └── parser.py            # Модуль извлечения Markdown-кода и очистки строк
│
└── prompts/                 # [EVOLUTIONARY KNOWLEDGE BASE] База промптов (файлы .txt)
    ├── sdd_architect.txt    # Шаблон проектирования архитектуры
    └── ...                  # Остальные роли (см. prompts.json)
```

------------------------------
## 3. Правила стабильности локального ИИ (Ollama Guardrails)
Для предотвращения галлюцинаций и сбоев локальных моделей (14B–30B), ядро и модули обязаны соблюдать три системных правила:

   1. Изоляция исполнения (Subprocess Run): Любые тесты (pytest, unittest) и компиляция кода запускаются исключительно через subprocess.run. Код возврата returncode == 0 является единственным критерием успеха. Поиск строковых маркеров (вроде "SUCCESS") в stdout запрещен.
   2. Текстовый протокол вместо JSON (ReAct Tool Calling): Локальные модели нестабильно работают с аппаратным format="json" при вызове инструментов. Вызов системных команд осуществляется строго через текстовые XML-подобные теги: <call name="tool_name">args</call>.
   3. Построчная очистка стриминга: При извлечении кода из ответов моделей, модуль parser.py обязан выполнять построчный .rstrip(), удаляя мусорные пробелы справа во избежание генерации SyntaxError: unterminated string literal.

------------------------------
## 4. Контур безопасности ядра (core.py)
Ядро является единственным мостом между ИИ и операционной системой. Оно обязано валидировать любые изменения, которые агент пытается применить к самому себе:

* Синтаксический барьер: Перед перезаписью любого модуля в папке modules/, ядро обязано скомпилировать сгенерированный код во временном файле через subprocess.run([sys.executable, "-m", "py_compile", "temp.py"]). Если returncode != 0, изменения блокируются, сырой ответ выводится в отладочную панель rich.
* Горячая перезагрузка (Hot Reload): При успешном изменении промпта или модуля, ядро обязано сбросить состояние памяти и перезапустить процесс через os.execv(sys.executable, [sys.executable] + sys.argv).

------------------------------
## 5. Протокол взаимодействия ролей (Цикл SDD -> TDD)
Каждая задача из tasks.json обрабатывается универсальным исполнителем (modules/executor.py) строго по конвейеру:

```text
[Манифест] ➔ [Глобальный Архитектор] ➔ Создание плана (tasks.json)
                                               │
 ┌─────────────────────────────────────────────┘
 ▼
[SDD Фаза] ➔ Создание архитектурного ТЗ (модель 30B)
 │
 ▼
[TDD Фаза] ➔ Написание unit-тестов ДО кода (модель 14B)
 │
 ▼
[Кодинг Фаза] ➔ Написание целевого кода в modern_src (модель 14B)
 │
 ├─► [Успех (returncode 0)] ➔ Статус задачи "completed"
 │
 └─► [Провал] ➔ [Фаза Критика] ➔ Авто-исправление кода (до 3 попыток)
                    │
                    └─► [Тупик] ➔ [Мета-Оптимизация Промптов] ➔ Перепись prompts/*.txt ➔ Hot Reload
```

------------------------------
## 6. Реестр изменяемости промптов (prompts.json)
Уровень автономии агента при изменении собственной базы знаний жестко контролируется флагом mutability в файле конфигурации:

* immutable: Агенту физически запрещено менять этот промпт (например, правила работы глобального архитектора).
* user_approved: Агент может сгенерировать улучшенную версию инструкции, но ядро приостановит конвейер и потребует ввода y/n в терминале от человека.
* autonomous: Полная свобода агента. Инструкции кодеров, тестировщиков и критиков адаптируются ИИ под особенности текущей задачи на лету.

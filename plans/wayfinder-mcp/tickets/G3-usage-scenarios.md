# [G3] Сценарии использования MCP-серверов агентом

**Тип**: grilling  
**Статус**: open  
**Метка**: wayfinder:grilling  

## Question

Как агент ai-agent использует эти два MCP-сервера в реальной работе?

Сценарии:

1. **Перед началом задачи:** агент вызывает `scan_project(path)` на статанализаторе, получает граф проекта. Пишет ключевые факты в память через `write_fact`.

2. **В процессе работы:** агент ищет функцию через `query_function(name)`, получает сигнатуру + контекст. Если нужно — пишет новые факты в память.

3. **При исправлении бага:** агент запрашивает память через `query_facts("login auth error")`, получает релевантные факты из прошлых сессий.

4. **При тупике (hot reload):** память сохраняет контекст между сессиями? Или теряется?

5. **Множественные проекты:** память общая для всех проектов или изолированная?

Конкретные вопросы:

1. Какие сценарии обязательны для v1?
2. Как часто агент пишет в память? На каждый шаг или только ключевые факты?
3. Нужна ли изоляция данных по проектам (namespace)?
4. Как память взаимодействует с трейсингом (traces/)? Дублирование или разделение?
5. Какие gate_trigger стратегии использовать?

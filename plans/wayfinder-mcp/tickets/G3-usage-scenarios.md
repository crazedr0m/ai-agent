# [G3] Сценарии использования MCP-серверов агентом

**Тип**: grilling  
**Статус**: open  
**Метка**: wayfinder:grilling  

## Question

Как агент ai-agent использует эти два MCP-сервера в реальной работе?

Сценарии:

1. **Перед началом задачи:** агент вызывает `scan_project(path)` на статанализаторе, получает граф проекта. Пишет ключевые факты в LOG16 через `write_to_substrate`.

2. **В процессе работы:** агент ищет функцию через `query_function(name)`, получает сигнатуру + контекст. Если нужно — пишет новые факты в LOG16.

3. **При исправлении бага:** агент запрашивает LOG16 через `query_substrate("login auth error")`, получает релевантные факты из прошлых сессий.

4. **При тупике (hot reload):** LOG16 сохраняет контекст между сессиями? Или теряется?

5. **Множественные проекты:** LOG16 общий для всех проектов или изолированный?

Конкретные вопросы:

1. Какие сценарии обязательны для v1?
2. Как часто агент пишет в LOG16? На каждый шаг или только ключевые факты?
3. Нужна ли изоляция данных по проектам (namespace)?
4. Как LOG16 взаимодействует с трейсингом (traces/)? Дублирование или разделение?
5. Какие gate_trigger стратегии использовать?
